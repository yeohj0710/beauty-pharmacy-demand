# 플랫폼별 제품 수요 조사 기준

## 공통 표본 설계

- 검색어: 제품당 2~4개. 정식명 전체보다 소비자 통칭을 우선한다.
- 검토 범위: 검색어별 상위 20개 결과.
- 채택 표본: 중복 제거 후 관련성 높은 자연 결과 최대 10개.
- 기본 기간: 최근 180일. 표본이 5개 미만이면 최근 365일까지 확장하고 확장 여부를 기록한다.
- 별도 집단: 광고·협찬, 브랜드 공식 계정, 판매 페이지는 자연 관심 표본과 분리한다.
- 결과 순서는 수요가 아니라 노출 신호다. 검색 순위와 참여 지표를 별도로 저장한다.

## YouTube

- 단위: 동영상 또는 Shorts의 `videoId`.
- 표본: 관련성 검색 상위 결과 중 최근 365일 최대 10개. Shorts와 일반 영상을 구분한다.
- 기록: 조회수, 좋아요, 댓글, 게시일, 채널, 콘텐츠 유형, 검색 순위, URL.
- 요약: 조회수 합계·중앙값, 댓글 합계·중앙값, 조회수/게시일수 중앙값.
- 주의: 오래된 대형 영상 하나가 지배하면 합계보다 중앙값과 일평균을 우선한다.

## Instagram

- 단위: 게시물 또는 Reel의 고유 URL.
- 표본: 키워드·해시태그 검색에서 확인되는 최근 180일 자연 결과 최대 10개.
- 기록: 콘텐츠 유형, 조회수(표시되는 Reel만), 좋아요, 댓글, 게시일, 계정, 검색 순위, URL.
- 분리: 협찬 문구, 공동구매, 브랜드 공식 계정, 판매 계정을 각각 플래그 처리한다.
- 주의: 저장·도달·공유처럼 화면에 보이지 않는 값은 `null`로 둔다. 로그인 개인화로 결과가 달라질 수 있으므로 계정과 수집 시각을 기록한다.

## TikTok

- 단위: 동영상 URL 또는 동영상 ID.
- 표본: 검색 상위 결과 중 최근 180일 자연 결과 최대 10개.
- 기록: 조회수, 좋아요, 댓글, 공유, 저장(표시될 때만), 게시일, 계정, 검색 순위, URL.
- 요약: 조회수 합계·중앙값, 참여 합계, 참여율 `(좋아요+댓글+공유)/조회수`, 게시 후 일평균 조회수.
- 주의: 동일 음원·챌린지라도 대상 제품을 식별할 수 없으면 제외한다.

## 네이버

- 단위: VIEW·블로그·카페의 정규화 URL.
- 표본: 통합검색 및 VIEW에서 관련성 상위 20개를 검토하고 최대 10개 채택.
- 기록: 결과 유형, 검색 순위, 제목, 게시일, 작성처, URL, 광고·체험단 표시.
- 요약: 채택 결과 수, 최근 30/90/180일 게시물 수, 순위 가중 노출점수 `Σ 1/log2(순위+1)`.
- 주의: 검색 결과 건수는 부정확하므로 수요 점수에 직접 사용하지 않는다. 체험단·판매글은 자연 후기와 분리한다.

## Google

- 단위: 자연 검색 결과의 정규화 URL.
- 표본: 광고·쇼핑·중복 도메인을 제외한 상위 20개를 검토하고 최대 10개 채택.
- 기록: 검색 순위, 제목, 도메인, 결과 유형, 게시일(확인 가능할 때), URL.
- 요약: 채택 결과 수, 고유 도메인 수, 순위 가중 노출점수 `Σ 1/log2(순위+1)`.
- Google Trends: 제품을 식별할 검색량이 충분한 경우에만 최근 12개월 관심도 중앙값과 최근 3개월 변화를 별도 기록한다.
- 주의: 검색 결과 총개수 문구는 사용하지 않는다. 쇼핑·광고·지도 결과는 자연 검색 표본과 합치지 않는다.

## 플랫폼별 점수

원시 지표는 플랫폼 안에서만 비교한다. 제품 집합 전체가 충분히 수집된 뒤 다음 순서로 0~100 점수를 만든다.

1. 조회·참여처럼 치우친 값은 `log1p` 변환한다.
2. 플랫폼·기간·콘텐츠 유형별 백분위로 변환한다.
3. 관련성 40%, 관심 규모 30%, 참여 20%, 최근성 10%를 기본값으로 둔다.
4. 지표가 없는 플랫폼은 원인을 구분한다. 검색해도 결과가 없는 것(no_results,
   Google no_data)은 관심 부족이라는 정보이므로 0점으로 반영하고, 수집
   실패(rate_limited 등)는 점수 분모에서 제외해 무벌점 처리한 뒤 신뢰도를
   낮춘다.
5. 표본 5개 미만은 `low confidence`, 5~9개는 `medium`, 10개는 `high`로 표시한다.

초기 가중치는 가설이다. 제품 전체 표본이 쌓인 뒤 사람이 오탐률과 재현성을 검토해 조정한다.

### 대시보드 가중 순위

대시보드의 순위는 플랫폼 간 원시 숫자를 직접 더하지 않는다. 각 플랫폼 안에서
양수 값의 백분위 점수(0~100)를 먼저 만든다. 0은 0점으로 두며, 수집되지 않은
값은 `null`로 보존한다.

- 네이버: 기준어 대비 최근 30일 관심도 70% + 최근 90일 관심도 30%
- Google: 최근 4주 관심도 70% + 최신 관심도 30%
- YouTube: 조회수 합계 70% + 조회수 중앙값 30%
- Instagram·TikTok: 조회수 70% + 참여 반응 30%. 참여 반응은 좋아요 + 댓글×4 + 공유×6 + 저장×2다.
- 한 플랫폼의 보조 지표가 전체 제품에서 모두 0이면 남은 유효 지표만 100% 반영한다.

현재 데이터 권장 시작값은 `네이버 35 · Google 10 · YouTube 25 · Instagram 15 · TikTok 15`다.
83개 수요 개체의 현재 수집 커버리지와 신호 재현성을 기준으로 둔 가설이며, UI에서 목적별
프리셋이나 슬라이더로 조정한다. 종합 점수는 `Σ(채널 점수×채널 비중) / Σ(측정된 채널 비중)`으로
계산한다. 수집 실패(`null`) 채널은 분모에서 제외해 무벌점 처리하고, 측정 범위는 근거
커버리지로 별도 표시한다. 검색 결과가 없는 것(0)과 수집이 실패한 것(`null`)을 구분하는
것이 핵심이다.

## 통계 보정과 판정 신뢰도

수집 원본은 그대로 보존하고, 점수 계산 전에 `scripts/audit-signals.mjs`가
다음 보정을 적용해 `app/signal-quality.json`을 만든다. `signals.json`을
갱신하면 반드시 이 스크립트를 다시 실행한다.

- **교차 제품 분할**: 같은 콘텐츠(동일 videoId·URL)가 k개 제품에 채택되면
  조회·반응을 k로 나눠 배분한다. 브랜드를 특정하지 못하는 비교·성분 콘텐츠가
  여러 제품에 이중 계산되는 것을 막는다. 공유 콘텐츠가 조회수의 50% 이상인
  채널은 브랜드 특정성이 낮으므로 신뢰도를 `low`로 강등한다.
- **기간 필터**: 프로토콜 기간(YouTube 365일, Instagram·TikTok 180일)을 벗어난
  콘텐츠는 보정 지표에서 제외한다. 제외 비율은 기록해 남긴다.
- **변화율 노이즈 하한**: 네이버 DataLab·Google Trends의 30일(4주) 평균
  지수가 1 미만이면 증감률을 표시하지 않는다. 0.1 → 0.16 같은 변화는
  지수 해상도 이하의 노이즈다.
- **이상치 지배**: 보정 후에도 콘텐츠 1개가 조회수의 70% 이상이면
  `outlierDominated: true`로 표시한다.
- **표본 기회 균등화**: 검색어를 많이 시도한 제품일수록 채택 콘텐츠가 늘어
  합계가 커진다(검색어 1개 제품 평균 3.3개 vs 3개 제품 10.6개 채택). 점수용
  지표는 상위 5개 콘텐츠 합계로 상한을 둔다.
- **무결과와 수집 실패의 구분**: 검색 결과 없음·Google no_data는 0점(관심
  부족 정보), rate_limited 등 수집 실패는 분모 제외(무벌점).
- **형평성 플래그**: 검색어 수 부족(2개 미만), SKU형 장문 검색어(최소 4토큰
  이상), 검색어 일부만 시도된 수집, 수집 실패를 제품별로 기록하고 UI에서
  보강을 안내한다. 전 제품의 90% 이상에 해당하는 격차는 전역 이슈로 한 번만
  보고한다.
- **채널 신뢰도**: 기간 내 표본 5개 미만 `low`, 5~9개 `medium`, 10개 이상
  `high`.
- **제품 판정**: 신뢰도 `medium` 이상 채널이 2개 이상이면 `usable`(판단 가능),
  일부 신호만 있으면 `caution`(주의), 그 외에는 `insufficient`(표본 부족).
  `caution`·`insufficient` 제품은 순위만으로 수요를 판단하지 않는다.
